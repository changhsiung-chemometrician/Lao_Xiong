Executive Summary

This report documents the construction of RUN_BoostedTrees_CmpClsfr.m, a MATLAB classifier that mirrors the I/O contract of the user's existing Naive Bayes and Logistic Regression siblings, dispatchable from the merge6 / ScanThruDropDown framework.

The function began as a textbook AdaBoostM2 implementation that collapsed catastrophically on a held-out-subject NIR glucose split (0.00 % external accuracy). Five iterative refinements later, it is now a deterministic, class-count-aware ensemble that achieves 87.08 % on the same data, handles K = 2 through ~60 classes without code changes, and produces reproducible results across runs.

Key engineering decisions: bagging over boosting for multi-class robustness, K-scaled tree depth and ensemble size, and seeded RNG by default for fair head-to-head comparison against deterministic siblings.

Naming Conventions

XGBoost is the popular brand. In the Python and R worlds it has become near-synonymous with the technique of gradient-boosted decision trees. But XGBoost itself is a specific third-party library by Chen & Guestrin (2016), and MATLAB does not ship it natively.

The closest built-in equivalent in MATLAB is the family of tree ensembles built via fitcensemble, sometimes called Gradient-Boosted Decision Trees (GBDT) or simply Boosted Trees. Both fit ensembles of shallow trees and aggregate them; the differences from XGBoost proper lie in regularization details (L1/L2 leaf penalties, column subsampling, sparsity-aware splits) rather than in the underlying recipe.

The function is named RUN_BoostedTrees_CmpClsfr.m to reflect what it actually uses. The header comments note that this is what XGBoost popularized, so any future reader following the XGBoost trail will find their way here without confusion.

First Run — The 0 % Disaster

The initial implementation followed the classical textbook recipe: fitcensemble with 'AdaBoostM2' for multi-class, shallow trees, modest learning rate. On the user's glucose NIR dataset (nT = 1401, nP = 356, 3 subject classes), this is what came back:

Zero percent — not chance level (~33%), zero. That margin is the diagnostic clue.

Diagnosis

Inspecting the .mat file revealed the structural problem behind the symptom. The class distributions in train vs. prediction sets were not balanced — they were disjoint:

Class distribution: train vs. prediction sets
ClassLabelTrain (n=1401)Pred (n=356)
1Subj-A7680
2Subj-B523356
3Subj-C1100

This is leave-one-subject-out validation: the prediction set is exclusively Subject B, held out from training entirely. The model's job is to generalize across subjects — the hardest possible split for any classifier, and a particularly cruel one for tree-based methods.

The mechanism of failure

The AdaBoostM2 warning — pseudo-loss from the last hypothesis is not positive — is the algorithm's polite way of saying: the first tree was already a near-perfect classifier on the training data, so I refuse to add any more.

What does “near-perfect” mean here? The first tree found a wavelength feature that cleanly separates the three training subjects — almost certainly a per-subject baseline offset, not anything related to glucose chemistry. Boosting saw zero training error and quit. The resulting single-tree model then assigned every Subject B sample to classes 1 or 3, never to class 2 (which it had learned to discriminate via the very feature it should have ignored).

The dataset's structure exposed a classic tree-ensemble pathology: trees readily latch onto subject-identity confounds when those happen to be more discriminative on the training set than the actual target signal. SVMs with RBF kernels are partially shielded from this because their smooth global decision surfaces resist axis-aligned shortcuts.

The Fix

Three coordinated changes restored sanity. None of them is exotic; together they turn a 0 % classifier into an 87 % one.

1. Bagging instead of AdaBoostM2

Bagged trees (random forest, 'Method','Bag') do not have a pseudo-loss early-exit mode. They train 500+ independent trees on bootstrap samples of the training data, each tree seeing a random subset of features at each split (NumVariablesToSample = sqrt(p) by default for classification). The vote across trees averages out the per-tree tendency to overfit subject identity.

2. Method auto-routing

A small subfunction local_resolve_method picks the right method given the problem:

function bm = local_resolve_method(req, nC)
    if strcmpi(req,'auto')
        if nC == 2
            bm = 'LogitBoost';
        else
            bm = 'Bag';     % robust default for K>2
        end
    else
        bm = req;
    end
    % high-K AdaBoostM2 still permitted, but with a warning
end

3. Warning capture

The pseudo-loss warning is now captured by lastwarn and surfaced explicitly in the output rather than silently buried in the console — so failures fail loudly.

Scaling to High Class Counts

The same defaults that work at K = 3 break silently at K = 60. Three hyperparameters now scale with the number of classes; one is downgraded for speed.

Why each scaling matters

Tree depth. A tree with MaxNumSplits splits has at most MaxNumSplits + 1 leaves. At K = 60, the previous default of 10 splits meant 11 leaves — mathematically incapable of reaching 49 of the 60 classes. The new max(10, 4K) rule gives 240 leaves at K = 60, with comfortable margin for purity.

Ensemble size. With more classes the decision surface fragments into more regions. Bagging variance reduction needs more trees to cover that surface adequately. 500 trees is enough at K = 3; you want 1000–1500 at K = 60 before returns level off.

Split criterion. The 'interaction-curvature' predictor selection runs chi-square tests at every candidate split — cost O(p·K) per node. At K = 60 with 100+ NIR wavelengths, this slows training by 50–100×. The function reverts to standard CART ('allsplits') once K > 12. Accuracy cost: usually small. Speed gain: dramatic.

Reporting also adapts to K. For K ≤ 10, per-class accuracy is printed as a full table. For K > 10, only the worst-five classes are printed; the complete K×K confusion matrix is always stored in out.ConfusionMatrix_P for later inspection.

Determinism

A subtle question, surfaced late in the development process: is this code reproducible across runs? The honest answer at first was no, even though the code carried a 'Reproducible',true flag.

That flag affects only parallel-worker split-finding determinism. It does not seed the bootstrap resampling or random feature subsampling that bagging performs at every iteration — both of which draw from MATLAB's global RNG stream. Two consecutive calls with identical inputs would produce slightly different ensembles.

The resolution

The function now calls rng(42,'twister') by default before any randomized fit. The seed is configurable, and run-to-run variance can be re-enabled for stability checks:

Determinism mode control via handles.RandomSeed

The decision to default on rather than off was driven by the merge6 / ScanThruDropDown comparison framework. Naive Bayes and Logistic Regression are deterministic by construction; comparing a randomized Boosted Trees head-to-head against them would conflate algorithmic performance with seed luck. Default determinism makes the comparison fair.

Discussion

Why does SVM still win, and is there headroom to close the remaining gap?

The structural mismatch

NIR spectra are continuous, highly collinear signals. Adjacent wavelengths share information; the chemically relevant features live in the joint covariance of many channels, not in any single wavelength. SVM with an RBF kernel works in an implicit infinite-dimensional space where smooth, globally curved decision boundaries are natural. PLS-DA succeeds for analogous reasons — its latent variables capture exactly the kind of multivariate covariance that chemometricians spend careers extracting.

Trees, by contrast, make axis-aligned splits one wavelength at a time. They cannot naturally express “the second principal component of channels 5–15” the way SVM or PLS-DA can. They can only approximate it with a staircase of single-channel splits, which is wasteful and brittle on noisy data.

Where to find the remaining accuracy

If matching SVM matters, the realistic path is not to keep tuning Boosted Trees on raw wavelengths. It is to preprocess the feature space so the tree splitter sees latent variables that already encode the relevant covariance:

  1. PLS → BoostedTrees pipeline. Run PLS-DA to obtain ~K latent variables, then train BT on those instead of the raw 25 wavelengths. The trees no longer fight subject-identity confounds because PLS already factored them out.
  2. PCA → BoostedTrees. Cheaper than PLS, captures most of the variance, but does not optimize for class separation.
  3. True XGBoost via xgboost-matlab. Gives L1/L2 regularization and column subsampling that fitcensemble lacks. Worth trying if a wrapper is already installed.

When BT will outperform NB and possibly SVM

The dataset matters. Boosted Trees will outperform NB whenever the conditional independence assumption is violated — which is essentially always with NIR data. BT will rival or beat SVM when the dataset has mixed feature types (continuous and categorical together), strong feature interactions that are sparse and identifiable, or natural axis-aligned structure (e.g. tabular business data, sensor thresholds, e-commerce features). NIR spectra are none of these. Business or behavioral datasets often are.

Take-Home Messages

What to remember when reaching for this classifier next time

  1. Always check class distributions before training. A 0 % external accuracy is rarely a tuning problem — it is usually a structural mismatch between train and test splits. Leave-one-subject-out is the harshest such mismatch and demands a method robust to subject-identity confounds.
  2. Prefer 'Bag' over 'AdaBoostM2' for K > 2. Pseudo-loss collapse is silent, devastating, and far more common than the documentation suggests. Bagging averages over independent trees and degrades gracefully where boosting fails catastrophically.
  3. Tree depth must scale with K. A tree with fewer leaves than classes is incapable of reaching every class — an obvious constraint that no MATLAB default enforces. Use roughly max(10, 4×nCls) as a sane lower bound on MaxNumSplits.
  4. Determinism is not free. templateTree('Reproducible',true) sounds like it makes things reproducible. It does not. Call rng(seed) explicitly before fitcensemble, and record the seed in your output struct.
  5. Trees are the wrong tool for NIR alone. They make axis-aligned splits on collinear features — the opposite of what NIR demands. If maximum accuracy matters, project to a chemometric latent space first (PLS / PCA) and then let the trees work in that space. Or use SVM.
  6. Honest reporting beats single-number accuracy. A K×K confusion matrix, per-class accuracy, and balanced accuracy together reveal failure modes that a single percentage hides — especially when class support is imbalanced or when some classes are absent from the test set entirely.
