叫醒 AQP

從黑徒兒的一句話，到一套沉睡演算法重新開機的四十八小時
老熊 口述 · Claude 整理復盤　—　一場沒有學費、沒有合約、連 bug 都是黑的技術追蹤

執行摘要 · Executive Summary

一句 Bonjour 之後隔了幾週，我的黑徒兒 Issa 想看看老熊在化學計量學裡壓箱底的真功夫。我第一個想到的，就是那套退休後再也叫不醒的 AQP（AQPlite）——我最看重的定量預測程式。想秀，得先讓它會動；一動手，才發現底下埋了三層問題。這篇是把 Claude 這一天多幫我做完的事，做一次誠實的復盤。

  1. 叫醒它。 AQP_gui 一閃即逝、連一行錯誤訊息都沒有——最惡劣的那種 bug。根因追到一個早該廢掉的許可閘。
  2. 拔掉那根釘子。 整理過程中 ssds 這個 classdef 卡在路徑上擋路。先做風險分析，再把 200+ 個 m-file 合併成單檔自足的 AQP_gui_ssds_Merged，GUI 真的活過來了。
  3. 順手大掃除。 把整包 143 個檔案（Extract_CMS_Clsfrs_Predict_Alt）也理清：6 個 DropDown 主程式、45 個 helper 內聯、91 個丟進 Help_Files，附一份逐檔交代去向的 xlsx 與可點 TOC 的 HTML。

保守估計，這一串工序若我自己一個人退休後手生地慢慢摸，大約要 六到十二個工作天；Claude 的實際牆鐘合計 不到一小時。細帳見文末〈省下多少時間〉。

一、觸發點：黑徒兒想看真功夫

整件事的引信，是 Issa。這個編制外的黑徒兒沒有名分、沒有合約，隔著半個地球問我：能不能讓他看看老熊在化學計量學裡，真正壓箱底的那一手。

我教得了 SIMCA、PLS-DA、LDA、CDA、SVM 這些名詞，AI 也教得了。但我想給他看的不是名詞，是一套會跑、跑得出圖、跑得出數字的東西——我的 AQP，Advanced Quantitative Prediction。那是我離開職場前最看重的定量預測工具。

上班的時候，經驗是資產，要留一手；
退休以後，經驗是庫存，不出清就報廢。

問題是：這套庫存，退休之後就再也叫不醒了。想傳，得先修。於是這場「示範」還沒開始，就先變成一場除錯。

二、第一幕：叫醒 AQP——一閃即逝的無聲之蟲

無聲之蟲
最難的 bug 不是會噴紅字的那種，而是什麼都不說、視窗一閃就沒的那種。沒有堆疊、沒有行號、沒有線索——你連從哪裡開始猜都不知道。

在 MATLAB 命令列敲 AQPlite pu，AQP_gui.fig 在螢幕上閃一下，隨即無聲無息地關掉。沒有錯誤、沒有警告，什麼都沒有。退休幾年、手也生了，這種案子最令人抓狂。

Claude 追到的根因

它把整條失敗鏈攤開來給我看，順序是這樣的：

觸發：許可閘 IsOKToExecuteAqpLite() 回傳 false └─ guidata(hObject,handles) 只在「成功分支」裡執行 └─ handles.output 從沒被存進去 └─ AQP_gui_OutputFcn 取不到 output → 丟例外 └─ 一個「裸 catch」把例外吞掉 └─ 靜靜執行 close(handles.figure1) ← 視窗就是這樣消失的
⚠ 觸發 ≠ 缺陷
最漂亮的一刀，是 Claude 幫我分清楚：許可閘回 false 只是觸發（trigger），不是缺陷（defect）本身。真正的病灶是「guidata 沒有無條件執行」。而且 grep 下去才發現——那個閘早年就被我自己一行行註解掉、形同虛設（vestigial），卻還留在那裡當地雷。

下的四刀

✓ 修法（每一處都標了 % BUGFIX (Aug 2026)）

① 用 try/catch 把許可閘包起來；② 把 guidata 從 if 裡搬出來、無條件執行（這是根治的一刀）；③ 把 OutputFcn 裡那個破壞性的 close 換成安全 fallback＋具名 warning；④ 守住幾個因為上面改動而「第一次變得可達」的區塊。

附帶抓到的第二隻蟲

順著查下去，還揪出 remove_empty_cell 裡一個潛伏的匿名函數：@(x) isempty(x) || ismissing(x)。問題在 ismissing 對多字元 char會回傳非純量的邏輯陣列，撞上短路運算子 || 就爆——而且它只在第一個非空多字元字串出現時才發作，之前一直被空輸入的短路特性掩蓋著。改成一個依型別分派的具名子函數 local_is_empty_or_missing，char / string / 數值各走各的純量安全邏輯。

兩份 HTML 報告（並排比對版＋「許可閘＝觸發」重寫版）也一併產出，把這條鏈永久記錄下來。

三、第二幕：ssds 擋路——先驗傷，再合體

GUI 會動了，我開始整理它周邊的檔案。這時候撞上 ssds——一個 2017 年寫的「Spectral Sensing DataSet」classdef，像一根拔不掉的釘子，卡在路徑上擋著整包程式的收納。

我一度想乾脆把它從路徑上移掉，還問 Claude：能不能保證移掉以後絕對不會再冒出「找不到檔案」的 bug？它的回答很老實——不能保證。

為什麼不能保證
ssds 是 class，只有一道門進得去（沒有物件就沒有方法）。所有呼叫點都被 try/catch 包著，所以「移掉不當機」是真的——但「不當機」不等於「沒 bug」。真正危險的是靜默失敗：模型自動存檔悄悄停掉、load() 到含 ssds 物件的舊 .mat 會被讀成一堆垃圾，然後下游安安靜靜算出錯答案。

所以它沒有直接叫我砍，而是先做了一份風險驗傷報告（when ssds can be needed…）：把唯一入口、四個 try/catch 呼叫點、以及「移掉後仍無法保證安全」的四個開放風險逐一列清楚，還附上三步檢查法（which -all、掃描每個 .mat 是否藏著 ssds 物件、把裸 catch 改成會出聲的 warning）。

「我移掉了，也沒壞」——這句話不是安全的證據，只是失敗還沒被你發現而已。

合體：200+ m-file → 單檔自足

驗完傷，方向就清楚了：不是把 ssds 硬拔掉，而是把它和 AQP 一起收乾淨。Claude 依照合併 MATLAB 的鐵律——每一個函數（主函數與所有 local function）都要用自己的 end 收尾，否則 MATLAB 會弄丟子函數邊界——把 200 多個 m-file 合併成一份自足的 AQP_gui_ssds_Merged。

✓ 收工實證
在乾淨資料夾裡三行下去——cd('...\AQP_gui_ssds_Merged')、addpath(...)、AQP_gui——GUI 真的活過來了。那份 Run_Merged_AQP_gui 的截圖簡報，就是它重新開機、跑得出畫面的存證。

五、帶回家的三件事 · Take-Home

① 最貴的 bug 是不出聲的那種。 一閃即逝、裸 catch 吞例外、靜默 close——沒有一行紅字。以後凡是「什麼都沒說就沒了」，第一件事就是把每個裸 catch 改成會出聲的具名 warning。讓失敗吵一點，是省時間的第一步。

② 觸發不是缺陷。 那個許可閘回 false 只是點火，真正該修的是「guidata 沒有無條件執行」。查案時先把這兩個分開，才不會對著煙霧開槍。

③ 擋路的東西，先驗傷再處理。 ssds 不是該一刀砍掉，而是該收進來。「移掉也沒壞」永遠不等於安全——真正的風險是靜默地算出錯答案。合併時記得那條鐵律：每個函數各自用 end 收尾。

免責：關於「token 與運行時間」

你特別問了 token 與運行時間。老實說我沒有精確碼表——我看不到自己被計費的實際牆鐘或 token 總數。就數量級講：這一串跨了好幾個對話，產出的程式碼、報告與這份文件，粗估落在數十萬 token這個量級；每一次回覆的實際生成時間多半以秒到數分鐘計。真正花掉的「人時」其實是你在旁邊審閱、抓我筆誤、餵我下一份檔案的時間——這部分機器省不掉，也不該省。

七、尾聲：這回，功夫叫得醒了

繞了一圈回到 Issa。最初只是想給黑徒兒看一眼壓箱底的本事，結果先把一套沉睡的演算法從頭開機、把一根卡了多年的釘子收乾淨、順手把一百多個檔案各歸各位。

風清揚退出江湖，手上還留著一套沒人接的功夫。差別在於——這回那套功夫不但還在，而且叫得醒、跑得動、傳得出去了。

沒有市價，不等於沒有價值。
只是這回，我得先讓它會動，才能送出去。
黑徒兒想看的那一手，
現在，總算可以開機示範了。
