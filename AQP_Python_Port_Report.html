The request

What was asked and what came back

You asked for AQP_gui_merged.m to be converted to Python, using the attached dataset to verify it before handing it over. Attached were the merged .m file, its .fig panel, the CS (FOSS, 102 samples), XRS (MicroNIR, 30 scans) and VAL (MicroNIR, 102 samples) workbooks, and the PP1_PP2 4‑scheme list.

The deliverable is a single file, AQP_gui.py. Run without arguments it opens the panel, rebuilt in tkinter from the .fig layout. With --cli it runs the same pipeline from the command line and saves every figure as PNG. Output folders and file names are the MATLAB ones (TMP_AQP, Result4OUT_cln_AQP, Result4FinalModels, Results4PRO, StepByStep), and results are written as .mat files your MATLAB tools can still open.

Why the Python file is about a fifth the size

  • Only the reachable code was ported. The merged .m file carries the whole helper library the GUI grew out of: SVR branches, UDM schemes other than woUDM, multi‑dataset MAT‑folder mode, the ssds class, string utilities and old experiments. The port follows the paths the panel can actually take.
  • Stages pass objects, not files. MATLAB handed every stage an Atrainpketc_*.mat file (later an in‑memory store) and re‑parsed file names to recover settings. Python passes data objects between stages and writes only the deliverables.
  • NumPy replaces loops and helpers. Many small MATLAB utilities (row/column forcing, cell unwrapping, find‑keyword helpers) become one numpy or Python built‑in call.
  • Fewer comments. The MATLAB file keeps years of dated change notes and commented‑out code (6,803 lines). The port keeps short comments that point back to the MATLAB function each part comes from.

Verification

How the port was checked

MATLAB is not available in the workspace, so the original .m file was run in GNU Octave as the reference. Two Octave functions behave differently from MATLAB's, so MATLAB‑exact versions of plsregress (SIMPLS) and sgolay were supplied to Octave. A thin layer let the Windows‑style paths in the code work on Linux. The algorithm code itself was not changed.

Each case below was run through both programs with the same panel settings. Every deliverable each one wrote (.mat, .csv, .xlsx) was compared number by number, as well as the RMSECV curve, the chosen PLS factor and RMSEP.

In every case the PLS factor and RMSEP were identical, the two programs wrote the same set of files, and the largest relative difference anywhere was about 1e‑11, which is floating‑point rounding. The GUI was also driven end to end on a virtual display: Load_DS, Run AQP, Compare / Show / Clear Results, both StepbyStep plot sets, a four‑run Scan Thru sweep with result collection, and close figs.

Two more set‑ups were tried and the original MATLAB code itself fails on both: a folder with only CS_*.xlsx (it stops after the self‑prediction step), and Spectra_Avg_T-Mean_P-All with XRS or VAL present (a "mismatch in length between Xhat and Xmeasure" error). The port runs the first with cross validation on the training set and raises the same error for the second.

Behaviour

Where the port differs from MATLAB

  • Left out: the .sam export (needs the Windows SamLibrary.dll) and the spoken messages. The PRO csv/xlsx files are still written.
  • Figures: open in their own windows in the GUI and are saved as PNG with --cli; the copies in Figs4OpmModel_AQP are PNG, not .fig.
  • PLS_Toolbox transfer schemes (GLSw, OSC, stdgen‑based PDS) report "unavailable". None are on the panel's menu.
  • CS‑only folder: runs here using cross validation on the training set; the MATLAB build crashed.
  • Result4FinalModels/4json is written even when a VAL set exists. In MATLAB that step errored in that case and was skipped silently.
  • Spectra_Avg_T-Mean_P-All is listed on the panel only for the administrator account, as in the original; --cli always accepts it.
Using it

Running AQP_gui.py

Needs Python 3.9 or newer with numpy, scipy, openpyxl and matplotlib, plus tkinter for the panel.

python AQP_gui.py                     # the panel
python AQP_gui.py -d 1 -w 1           # panel, progress and warnings in the console
python AQP_gui.py --cli --ds DS_full --ana Brix
python AQP_gui.py --cli --ds DS_full --ana Brix --pp-xlsx pp1_pp2_4schemes_AQP_1st_2ndDer.xlsx
python AQP_gui.py --cli --ds DS_full --ana Brix --scan cPP2=SNV,none --scan CabXfer_scheme=MDC,PDS99[w1] --compare
python AQP_gui.py --cli --help        # every option
