1. Summary

The goal was to fold every m-file in SVM_gui_ALL-mfiles.zip into the GUIDE program SVM_gui.m as local functions, using the saved skill matlab-merge-mfiles. Its main rule is that every function gets its own matching end.

Most of the work was the audit, not the concatenation. A merge can pass every static check and still break at run time wherever code depends on which file a function lives in. Examples are which(), dbstack names, implementations swapped with addpath, and code found on the path that can't see local functions. One of these got past v1 and showed up as the kw2skw error, which v2 fixed. v3 then merged the remaining files: cmap_DPR became a small dispatcher that keeps the default/alternate colour-scheme switch working, and only the class ssds.m is left as a separate m-file.

5. Running the merge, and two parser bugs

The skill's script merge_mfiles.py does the concatenation, the end-termination, the collision renaming and a self-check. It failed twice on this codebase, and both failures were genuine gaps in its parser.

5.1 Crash: function headers split across lines

Five files declare their function across several lines with ..., e.g.

function [SVM_models_4C320,metpathfilename]...
    =implement_SVMpred_gui(TPinfo_loaded,SVMmodels_sort, ...);

The header pattern found no function name, which caused a KeyError. Fix: the headers were joined onto one line in the staged copy (line count kept). Files: LinkGraph_Y1_smellprint_PCA2D, LinkGraph_Y1_smellprint_scale_and_UNscaled, implement_SVMpred_gui, pcascore_all, plotresp_T_clsoffset_wP_eaFeat_origscale.

5.2 Self-check failed: the parser misread quotes and block comments

[verify] functions=236 function_ends=235 stack_leftover=3 paren_depth=2 → NOT BALANCED
  1. csv2struct.m, line 48: format = [format '%f'];
    Inside [ ] or { }, a quote that follows a space starts a string, even right after an identifier. The parser treated it as a transpose. The % in '%f' then looked like a comment and swallowed the closing ].
  2. getCases_in_switch.m: a %{ … %} block comment before the function line
    Its first "code" line looked like 2018/June, so the file was classified as a script and kept out of the merge.

Fix: a patched working copy (merge_v2.py; the saved skill was left untouched) with a parser that:

  • treats a quote after whitespace inside [ ]/{ } as the start of a string;
  • blanks %{ … %} block comments across lines (nesting allowed);
  • blanks everything after a ... continuation;
  • handles double-quoted strings, including the doubled-quote escape "".

8.2 The cmap_DPR dispatcher

Before the merge, MATLAB itself chose the colour scheme (current folder first, then path):

  • Default: cmap_etc\cmap_DPR.m, or the copy next to SVM_gui.m.
  • Alternate: cmap_etc\attic_cmap_alt\cmap_DPR.*, switched on by cmap_DPR_Alt_LM_KeepColorScheme_in_GM (rmpath cmap_etc, addpath attic) and off by cmap_DPR_reset_default_path.
  • Forced default: cmap_DPR_customerized cds into cmap_etc so the default wins even while the alternate is on the path.

In v3 the original code became the local function cmap_DPR__default, and a new local cmap_DPR defers that choice to MATLAB by asking the base workspace, which can't see local functions:

function varargout = cmap_DPR(varargin)
nout = max(nargout,1);
w = '';
try
    w = evalin('base','which(''cmap_DPR'')');     % what MATLAB itself would pick
catch
end
if ~isempty(strfind(lower(w),'attic_cmap_alt'))    % alternate scheme is active
    tmpName = 'tmp_args_4_cmap_DPR_alt__';
    assignin('base', tmpName, varargin);
    cleanupObj = onCleanup(@() evalin('base', ['clear ' tmpName]));
    [varargout{1:nout}] = evalin('base', ['cmap_DPR(' tmpName '{:})']);
else
    [varargout{1:nout}] = cmap_DPR__default(varargin{:});
end
end

12. Lessons and checklist for future merges

  1. Inventory first. Classify every file (function, script or classdef) after blanking block comments; find other main programs or GUIDE GUIs to exclude.
  2. Search for file-identity code: which(, exist(…,'file'), nargin('name'), dbstack .name comparisons, mfilename, eval/evalin strings, string callbacks (in code and in the .fig).
  3. Search for implementations swapped by path (addpath/rmpath/cd). Either keep them standalone, or merge them as a dispatcher that asks the base workspace's which and calls the outside version only when MATLAB would have picked it (v3 pattern).
  4. Anything found on the path needs its helpers on the path too: kept-separate files, external copies the code may add to the path, and .p files.
  5. Check whether scripts are actually run. References inside if false example blocks don't count; those scripts can be left out.
  6. Make sure the parser handles real MATLAB syntax: [a 'str'] strings, %{ %} block comments, ... tails, double-quoted strings, and function headers split with ....
  7. Normalise encoding (Latin-1 to UTF-8); write CRLF back for Windows.
  8. Check three ways: the balance check, an independent Octave parse, and a coverage audit. For behaviour tests in Octave, run clear name; rehash after each cd/addpath, because Octave caches function lookups where MATLAB doesn't.
  9. When an error comes back, compare the traceback line numbers with each candidate file to find which copy actually ran.

16. How the work was done: tools and test harness

16.1 Analysis tools (Python)

ToolWhat it does

23. The button bug: "Clsname_2D_PCASVM_gui is not found" (request 3)

23.1 Cause, and a miss in the Nov 9 audit

The buttons are created in code with a string callback: 'callback', ... followed on the next line by 'Clsname_2D_PCASVM_gui', .... MATLAB evaluates a string callback in the base workspace. Before the merge, that function was its own file on the path. After the merge it is a local function, which the base workspace can't see.

The Nov 9 audit (§4.2) reported "string callbacks: none found in code". That search missed the multi-line form, where the string sits on the line after 'callback', .... The new scan joins continuation lines first.

24.3 Lessons added to the checklist (§12)

  1. Search callbacks after joining ... lines. A string callback on the next line looks harmless to a line-by-line search. Convert local targets to @(~,~) f(), never a bare @f: that would pass (src,evt) into a function whose first input is optional.
  2. Test by pressing buttons, not only by parsing. Make the button's figure current, because many callbacks read get(gcf,'userdata'). A pre-fix build must reproduce the reported error.
  3. A path-switched implementation is still a local-drive dependency. Replace the path swap with in-memory state; it holds the same information without the folder.
  4. Prune by reachability from the .fig callbacks. In a single-file merge, half the code was unreachable.
  5. Record a baseline from the original first, then compare every number. The comparison is what makes an aggressive refactor safe.
  6. Octave is a usable test bench for MATLAB GUIs with a test-only compatibility layer, as long as both versions run under the same layer.

These lessons were also proposed as an update to the matlab-merge-mfiles skill ("the third rule: string callbacks run in the base workspace").
