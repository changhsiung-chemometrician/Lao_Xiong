04 · Converting the code

A line-by-line numerical engine in one file

  • Numerics copied exactly, not approximated. MATLAB's plsregress (SIMPLS, including its double orthogonalisation), sgolay, knee_pt, stdgen99/stdize99, GLSstd, the RMSE definitions and the fold assignment were all ported statement by statement.
  • Same outputs, same names. Every deliverable (Results_AQP, Beta_etc_FinalModel, OpmModel, StepByStep Atrainpketc files, PRO csv/xlsx) is written as a MATLAB .mat or the original format, with the original folder and file names, so your MATLAB tools still read them.
  • Stages pass data in memory. The MATLAB build handed each stage an Atrainpketc file and re-read settings from file names; Python passes objects and writes only the deliverables.
  • Two ways to run. python AQP_gui.py opens the panel (tkinter + matplotlib); python AQP_gui.py --cli --ds <folder> --ana Brix … runs without it and saves figures as PNG.

06 · Round 1

Making the panel look like the MATLAB one

What you saw

A stretched panel with six extra controls (AQP_class, Xfer-PP, woUDM, TcvModelParaOpmScheme, Lines_Xticks, Val_Exist), grey combo boxes and small fonts.

Cause and fix

Those six are hidden in the .fig (Visible off), so they're now hidden but still read. MATLAB's character unit is 1 : 2.63 (measured from your screenshot), not my 1 : 2.25, and fonts use the .fig point sizes unshrunk. Drop-downs, buttons and labels were redrawn in MATLAB's Windows style, and the program declares itself DPI-aware so text stays sharp.

07 · Rounds 2 and 3

Grid lines, colours and the analyte picker

Yellow MN grid too dark

matplotlib's 'y' is a dark olive (0.75, 0.75, 0); MATLAB's is pure yellow [1 1 0]. I also drew the 125 lines at 1.5 pt instead of MATLAB's 0.5 pt, so they formed a solid block over the spectra.

Fix

Pure yellow 0.5 pt lines drawn behind the spectra, over a pale band so they don't beat into stripes. MATLAB's green, cyan and magenta now replace matplotlib's darker versions in every plot.

Analyte picker hard to see

A small box that opened in the top-left corner. After the first fix it was larger but Windows still parked it there, because a position given before the window appears can be ignored.

Fix

2.5× larger with 16-point text and MATLAB's "Select from the following:" and FINISH. Every dialog is now built hidden, positioned in the middle of the monitor holding the panel, then shown; the position is applied again just after. You confirmed it on Windows.

08 · Round 4

Data Tips and Edit Plot on every figure

Compare Results already had data tips; RMSEP_summary and the other figures didn't, and none had MATLAB's Edit Plot. I replaced the one-off code with a general layer installed on every figure window.

Data Tips

  • On by default. Click near any data point on any line, marker or scatter to pin an X/Y box at the nearest real point.
  • Up to 6 significant digits, as in your MATLAB screenshot (1.57724).
  • Overlapping lines give one tip; reference lines give none.
  • Click again to remove; Delete or Esc clears all.

Edit Plot

  • MATLAB's arrow button on the toolbar.
  • Drag the legend, titles, axis labels, texts and tip boxes; the selection gets a dashed frame with handles.
  • Delete removes the selected object.
  • Data Tips, Edit Plot, Pan and Zoom exclude each other; keys d and e switch.

Tested with 19 automated checks driven by real mouse and key events (tips, overlapping lines, all four drag targets, Delete, mode switching), plus the full GUI test and the MATLAB comparison. Along the way I fixed a small bug: windows closed by a multi-scheme run stayed in the panel's window list.

13 · Known differences

Where the port still differs from MATLAB

  • Left out: the .sam export (needs the Windows SamLibrary.dll) and spoken messages. PRO csv/xlsx files are still written.
  • PLS_Toolbox transfer schemes (GLSw, OSC, stdgen-based PDS) report "unavailable"; none are on the panel menu.
  • Panel toolbar: MATLAB's figure toolbar strip on the panel itself is not reproduced (plot windows have their own).
  • Fonts: Arial on Windows; text widths can differ from MATLAB's by a pixel or two.
  • Command-line mode saves PNG files, which can't have Data Tips or Edit Plot.
  • Figure tools were tested with matplotlib 3.11 only; the skill's self-test checks them on your version.
  • Spectra_Avg_T-Mean_P-All appears on the panel only for the administrator account, as in the original.

14 · Take-home messages

What to remember from this session

  1. The Python version can replace the MATLAB one on this data. Same models, same RMSEPs, same files, 11–33× faster than the original running in Octave.

  2. Comparing every output file mattered. RMSEP matched early on, but file-level checks found four port defects that the headline numbers alone would have hidden.

  3. Most visual differences came from defaults. MATLAB's character units, its 'y' colour, line widths and Windows window placement all differ from matplotlib's and Tk's. Future ports should check these first.

  4. Testing on your Windows machine was essential. The dialog-placement problem never appeared on my Linux test screen.

  5. The figure tools are now reusable. The saved preference and skill mean every Python figure I write for you gets Data Tips and Edit Plot automatically.

  6. One check worth doing: run tests/test_figure_tools.py from the skill zip once on your Windows machine to confirm the figure tools with your matplotlib version.
