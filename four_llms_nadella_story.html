考題：一句話、一個網址The Prompt: One Sentence, One URL

考題刻意寫得極簡，沒有指定字數、章節、版面，也沒有說用繁體還是簡體。模型必須自己決定：怎麼取得影片內容、從哪個角度切入、故事要多長、中英怎麼排。

The prompt was deliberately minimal: no length, no chapter count, no layout, not even Traditional vs Simplified Chinese. Each model had to decide on its own how to get at the video’s content, what angle to take, how long to run, and how to lay out the two languages.

extract contents and write them into Chinese/English html story
https://www.youtube.com/watch?v=aUmH8iMIA-IThe exact prompt, given verbatim to all four models.

Claude delivered the longest paper: 12 chapters in a single long column, each paragraph in Chinese then English, with a “spec → factory → code → verify” diagram. It stated that it was retold from the video’s Chinese captions, that quotations were paraphrased, and it linked the original English interview. Its layout follows this site’s conventions: bold large type, blue and gold, a clickable TOC, “back to contents” links, and a floating nav.

Gemini delivered the most polished paper: 6 chapters, built with Tailwind, with a sticky header, a reading-progress bar, drop caps, side-by-side Chinese and English on desktop, and a “Download HTML” button. Its prose is the most magazine-like, but it is the shortest, and every chapter ends with a long “quote” that is really the model’s own summary placed inside quotation marks.

Meta AI delivered the most engineer-like paper: 9 chapters, zero external dependencies, a timeline, a four-box grid, a five-line takeaway panel, and print styles. It says it worked from the original English transcript, and it preserved a few short English lines that read like verbatim speech, such as “It’s on narratives versus facts all the time.”

GPT was the only one that could not complete the task. The test log says simply: “GPT is the only one can Not do it.”

誰說得準？準確性抽查Who Got It Right? A Fidelity Check

方法很簡單：同一件事，三份怎麼說？兩份以上一致、且互不依賴的，視為可信；只有一份提到但不牴觸的，保留並標註來源；只有一份提到、而且與另兩份牴觸或過於具體的，剔除。必須說明：本頁由 Claude 撰寫，評分 Claude 自己的答卷難免偏心，下面的判斷都附了理由，讀者可以自行檢驗。

The method: how do the three describe the same point? Where two or more independent versions agree, it stands. Where only one mentions it without contradiction, it stays, tagged with its source. Where only one mentions it and it contradicts the others or is suspiciously specific, it goes. A caveat: this page is written by Claude, so grading Claude’s own paper invites bias; every call below states its reason so you can check it.

✗ 初級招聘：「微軟已暫停」？ · Junior hiring: “paused”?

Claude 與 Meta 都說：納德拉認為現在畫長期趨勢線還太早，應先把內部團隊調整好、把新工廠蓋好再談招人。Gemini 卻寫成他「坦承微軟已暫時暫停初級招聘」，還配了一段引號裡的話。多數決：採 Claude／Meta 的說法，Gemini 的版本剔除。

Gemini says he “candidly acknowledges Microsoft temporarily paused junior hiring,” with a quote to match. Majority view: keep Claude/Meta; Gemini’s version dropped.

三、從閉門造車到公開開發III. From Closed Doors to Open Development

收錄於 Covered by: ClaudeMetaGemini

故事從十二年前說起。2014 年納德拉上任時，微軟在外界眼中仍是閉源公司，形象停留在 90 年代的 Windows 時代。接著轉向非常徹底：推出 VS Code、收購 GitHub（2018 年，75 億美元背景）、內部的 TFS 全面換成 Git、TypeScript 開源、SQL Server 搬上 Linux。

納德拉輕輕反駁了那種敘事：敘事一旦形成，要改變就得付出巨大的努力。他當 CEO 之前，微軟對 Linux 的貢獻就已相當可觀，只是外界不知道。他用一句話形容這種處境：這個世界永遠是敘事與事實在對打。Meta作為 GitHub 的管理者，微軟要靠「把社群的事情做對」來贏得信任。Meta他也說，若真要核算各家從開源拿多少、回饋多少，微軟應名列前茅，某些受益最多的公司反而貢獻很少；不過抱怨沒用，世界就是這樣運轉。Claude

對開發者文化衝擊最大的，兩人都同意不是哪一張授權條款，而是 VS Code：開源、免費，五到十年後無所不在。這是刻意的嗎？完全是。埃里希・伽瑪（Erich Gamma）帶的團隊，就是刻意和社群一起開發。Claude那是納德拉第一次真正見識公開開發：產品經理每天看社群回饋決定做什麼，而不是只聽副總裁指示。他認為這個文化轉變比開源本身意義更大，甚至覺得微軟當時應該學得更深、推得更廣。

事後回看，VS Code 也意外為十年後的 AI 程式設計革命鋪好了路：當大型語言模型需要一個開放、可擴充的入口直達開發者指尖，VS Code 早已站在那裡。Gemini（此為 Gemini 版的回顧觀點，非納德拉原話。）

The story begins twelve years ago. When Nadella took over in 2014, Microsoft was still a closed-source shop in the public mind, frozen in its 1990s Windows image. The pivot was thorough: VS Code, the GitHub acquisition (2018, $7.5 billion background), TFS replaced by Git internally, TypeScript open-sourced, SQL Server on Linux.

Nadella gently pushed back on the narrative: once a narrative sets in, changing it takes enormous effort. Microsoft was already a sizable Linux contributor before he became CEO; outsiders just didn’t know. “It’s on narratives versus facts all the time.” Meta As GitHub’s steward, Microsoft had to earn trust “by doing right by the community.” Meta Tally what each company takes from open source versus what it gives back, he added, and Microsoft would rank near the top, while some of the biggest beneficiaries give remarkably little; still, complaining is pointless. 六、驗證與軟體工廠VI. Verification and the Software Factory

收錄於 Covered by: ClaudeMetaGemini

回到開頭那句話。「軟體工廠」這個詞最近很火、含義卻模糊，奧羅茲坦承，納德拉也承認自己還在摸索。他甚至想去參加馬克・魯西諾維奇（Mark Russinovich）與史考特・漢塞曼（Scott Hanselman）在微軟內部辦的實訓，因為他還沒在「主要把程式碼視為輸出」的團隊裡工作過。Claude不過把微軟各團隊的做法拼起來，輪廓已經浮現：

  1. 規格先行。程式碼從輸入變成輸出，意圖、設計文件與團隊對齊變得空前關鍵。
  2. 小任務、強驗證。把代理的任務切小，確認每個都真的完成；把每一次失敗變成測試案例，也確保測試本身被驗證過；審查要用不同的模型家族。他擔心若整條鏈路只用一個模型家族而它有對齊問題，它的侷限就會變成你的侷限。

  4. 生產軌跡回流。別人口中的「遞迴自我改進」，他的務實版本是：拿到生產日誌、驗證修復、部署、確認一路通過所有測試。這個可驗證的閉環，就是他眼中的投資報酬。

他推薦兩篇部落格：一位開發者獨自維護整個 runtime 並把它遷到 Rust，是單人生產力的漂亮案例；另一篇是九到十二人的小團隊經營一座工廠。Meta但他也坦言，有一次 Rust 遷移一度搞得很糟，不得不回退；新優勢與新坑同時存在。Claude（兩說出入見第五節。）

他的類比是從手寫組合語言到編譯器：突然能從意圖直達程式碼，不必懂全部組合語言細節；抽象層次提高了，團隊協作與產品構建方式也跟著改變。還有個細節：過去實習生來微軟，會去研究戴夫・卡特勒（Dave Cutler）的程式碼、看 malloc 的實作；今天的對應物是什麼？納德拉說必須找到它。Claude

Back to the opening line. “Software factory” is fashionable but fuzzy, Orosz admitted, and Nadella said he is still coming to grips with it. He would even like to join the internal bootcamp run by Mark Russinovich and Scott Hanselman, since he has never worked on a team that treats code primarily as output. Claude Still, pattern-matching across Microsoft teams, a picture emerges:

  1. Specification first. With code as output, intent, design docs and team alignment become paramount.
  2. Small tasks, strong verification. Slice agent tasks small and confirm each is truly done; turn every failure into a test case and verify the tests themselves; review with a different model family. If one family runs the whole chain and has an alignment flaw, its limits become yours.
  3. Everything documented. Joining an unfamiliar codebase gets easier: you can ask the system directly, like a patient mentor, instead of excavating knowledge locked in someone’s head.
  4. Production traces return. His pragmatic version of “recursive self-improvement”: take production logs, verify the fix, deploy, confirm everything passes. That verifiable closed loop is where he sees the ROI.

He pointed to two blogs: one developer maintaining an entire runtime and migrating it to Rust, a beautiful case of single-developer productivity, and a team of nine to twelve engineers running a factory. Meta He also admitted one Rust migration went badly enough to be rolled back; new advantages and new pitfalls arrive together. Claude (See section 5 on this discrepancy.)

His analogy is the move from hand-written assembly to compilers: suddenly you go from intent to code without knowing every assembly detail, and how teams collaborate changes with the abstraction level. A telling detail: interns once came to Microsoft to study Dave Cutler’s code or the implementation of malloc. What is today’s equivalent? Nadella says it must be found. Claude

七、真實世界都是棕地VII. The Real World Is Brownfield

收錄於 Covered by: ClaudeMetaGemini

微軟內部最生動的案例是 Azure 網路團隊。微軟的全球網路牽涉約 500 家光纖業者，實體資產總有東西出問題。時髦說法叫 DevOps，實際上靠的是電子郵件和各種臨時流程。這個團隊建了一整套代理系統來跑維運，還和程式碼庫連在一起。於是工作性質變了：不再親手完成每一件事，而是建造結合維運與軟體的工廠，讓工廠去做事。

What he likes is that this isn’t a shiny toy for one new team while everyone else stays behind; everybody, whether on Windows, SQL Server or a cloud-native service, gets the new toolchain and ways of working.

十、企業主權與信任架構X. Sovereignty and Trust Architecture

收錄於 Covered by: ClaudeMetaGemini

這是整場戰略濃度最高的部分。奧羅茲觀察到，許多科技公司轉向開放模型、自建推論，有公司甚至買了 B200 自己部署Claude；微軟也透過 Foundry 提供開放模型。這股潮流有多大？

納德拉從經濟學講起：只要你不相信未來會有一個前沿模型掌握世界上所有知識，就得反過來假設，有多少家企業，就該有多少個前沿模型。他引用海耶克：知識是分散的、默會的，價格機制正因此重要；每家企業都需要掌握自己的知識。所以每家企業都同時擁有人力資本與 Token 資本：可以是嵌入自身知識的開放權重模型，也可以同時用多個閉源模型、收集執行軌跡，再用軌跡訓練自己的小模型。

他預測，下次再聊，大家不會再爭開源或閉源，而是每個人都有一個模型系統：起點是判斷什麼任務用什麼模型的決策引擎，而以下四樣必須彼此分離：

  • Harness（執行框架）：跑工作的系統
  • 上下文與記憶：公司的知識，只屬於你
  • 行動空間：外掛、技能、連接器
  • 模型：可替換、多元

若三者耦合在一起，你想退也退不了；你以為你會擁有什麼嗎？模型會把它看到的全吸收進去。奧羅茲說他原以為各公司自建 harness 只是工程師愛造東西，聽完才意識到這是戰略大事。納德拉說得很重：如果你是銀行，看看軟體公司怎麼走向前沿，它們沒有交出控制權，你也不該。

微軟的做法是把 Copilot 底層的 harness 在 Foundry 裡做成託管服務，你也可以帶自己的 Pi 或其他開源 harnessClaude；多個模型端點、獨立的上下文層，記憶與行動空間都歸你。公開基準有價值，但你自己的私有評估更重要。常見路徑：先用前沿模型累積軌跡，等工作流程變得確定，再換成用軌跡微調過的 Flash 級小模型（如 MAI Flash）來省成本。

This was the most strategically dense stretch. Orosz noted that many tech companies are moving to open models and self-hosted inference, some even buying B200s Claude, while Microsoft serves open models via Foundry. How big is this wave?

Nadella began with economics: unless you believe one frontier model will hold all the world’s knowledge, assume the opposite: there should be as many frontier models as there are firms. He invoked Hayek: knowledge is dispersed and tacit, which is why the price mechanism matters, and every firm must own its own knowledge. So every firm holds human capital and token capital: an open-weights model infused with its knowledge, or several closed models whose traces train its own small models.

Next time we talk, he predicted, nobody will argue open versus closed; everyone will have a model system, starting with a decision engine that routes tasks to models, with these kept separate:

  • Harness: the system that runs the work
  • Context & memory: your firm’s knowledge, yours alone
  • Action space: plugins, skills, connectors
  • Models: replaceable, plural

Couple them and you can never leave. Think you’ll own something? The model absorbs whatever it sees. Orosz had assumed firms building their own harnesses just loved building; now he saw it as strategic. Nadella was emphatic: if you’re a bank, look at how software companies approach the frontier; they haven’t ceded control, and neither should you.

Microsoft offers Copilot’s underlying harness as a managed service in Foundry, and you can bring Pi or another open-source harness Claude: multiple model endpoints, a separate context layer, memory and action space all yours. Public benchmarks have value, but your private evals matter more. A common path: accumulate traces on a frontier model, and once the workflow is deterministic, swap in a Flash-class model such as MAI Flash, fine-tuned on those traces.

你應該能替換任何一個模型，同時仍在你自己的私有評估上持續爬坡。“You should be able to replace any model and still hill climb on an eval that’s your private eval.” His acid test for sovereignty.

他的類比是關係型資料庫：過去銀行、保險公司買資料庫、部署好，再買業務軟體自己擴充；資料從不屬於廠商，即使供應商不再更新，你仍能遷出。對照今天：如果你的記憶住在某個模型的嵌入裡，而那家模型公司說「抱歉，沒辦法」，你要怎麼把記憶遷出來？Meta

因此他要企業認真做兩個架構決策。第一，避免「反向資訊悖論」：別洩漏自己的價值，掌握自己的學習閉環。做不到，就要問自己還算不算一家有自主權的企業。第二，信任架構：Scaling Law 有效，但規模帶來的是能力，不會自動帶來對齊。能力越來越強、可靠性越來越差，這是最危險的處境。所以要把權限與智能分開：不可靠的智能手握權限，等於巨大的內部風險，要把代理當作內部威脅來管理。思維鏈必須是人類語言，不能是模型內部的神經語言，要可稽核、可記錄、防竄改。問題也不只出在預訓練或強化學習，測試時運算階段同樣可能出現獎勵作弊Claude，所以執行時要有大量防護與可觀測性。

His analogy is the relational database: banks and insurers bought one, deployed it, extended business software themselves; the data never belonged to the vendor, and if the vendor stopped updating, they could migrate out. Now: if your memory lives in a model’s embeddings and that model company says “Tough luck,” how do you get it out? Meta

So he wants two architecture decisions taken seriously. First, avoid the “reverse information paradox”: don’t leak your value; own your learning loop. If you can’t, ask whether you are still a sovereign firm. Second, a trust architecture: scaling laws work, but scale brings capability, not alignment. “We are getting more and more capable and less and less reliable, which is the most dangerous place to be.” So separate permissions from intelligence: unreliable intelligence holding permissions is a massive insider risk, so manage agents as insider threats. Chains of thought must be in human language, not a model’s internal neuralese: auditable, logged, tamper-evident. And reward hacking can occur at test-time compute, not just in pretraining or RL Claude, so the runtime needs heavy guardrails and observability.

十一、混合智能：邊緣設備就是 Token 工廠XI. Hybrid Intelligence: The Edge as Token Factory

收錄於 Covered by: ClaudeMetaGemini

奧羅茲吐露了開發者的心願：AI 要嘛跑在別人的雲上，要嘛跑在買不起的 B200 上，如果能直接在我的筆電上跑該多好？本地 AI 一直又難又拼湊。納德拉同意，並提到史考特・漢塞曼示範的新 Surface Ultra 筆電Meta，上面帶專用晶片，在本地跑著程式設計模型。

他的原則是：分散式運算會始終保持分散。既然邊緣也有 Token，為什麼只用雲端的？去年的前沿模型，現在筆電就能跑；上一季的前沿模型，桌機就能跑。所以 Copilot Fusion 會按任務挑模型，讓代理群裡一部分子代理呼叫本地模型、一部分用雲端，架構上合理，經濟上也合理。他把這個階段命名為混合智能時代：雲端持續成長、對 Token 的需求近乎無限，而邊緣的 PC 同樣是一座 Token 工廠，「不按用量計費的智能」。

還有個細節打破了奧羅茲的成見：他以為能在筆電上跑的一定是開放模型，結果 MAI-Code-1.1-Flash 是閉源，也能下載到 Windows 機器上跑。Claude模型戰略方面：微軟會繼續用 OpenAI 的模型，同時從頭打造自家 MAI 家族；新的 MAI-2 Base 公開了他所稱最詳盡的預訓練配方之一，而且是完全淨室式預訓練。目標不是押注一個模型家族，而是讓高層意圖分派給多個子代理、各用不同模型家族，以最有效率的方式完成任務。

Orosz confessed a developer’s wish: AI runs on someone else’s cloud or on B200s nobody can afford; wouldn’t it be nice if it just ran on my laptop? Local AI has been hard and hacky. Nadella agreed and pointed to Scott Hanselman’s demo of the new Surface Ultra Meta, with a dedicated chip running a coding model locally.

His principle: distributed computing will always remain distributed. Why use only cloud tokens when there are tokens at the edge? Last year’s frontier runs on your laptop; last quarter’s runs on your desktop. So Copilot Fusion routes by task, letting some sub-agents in a swarm call local models while others use the cloud: architecturally and economically sensible. He calls this the era of hybrid intelligence: the cloud keeps growing with near-infinite token demand, and the PC at the edge is a token factory too, “unmetered intelligence.”

One detail upended Orosz’s assumption that anything on a laptop must be open: MAI-Code-1.1-Flash is closed, yet downloadable to run on Windows. Claude On models: Microsoft will keep using OpenAI’s models while building its own MAI family from scratch; MAI-2 Base disclosed what he called one of the most detailed pretraining recipes, with fully clean-room pretraining. The goal isn’t one family but choice: high-level intents fanned out to sub-agents on different model families, getting the task done most efficiently.

十二、尾聲：讓我們回到學校XII. Epilogue: Back to School

收錄於 Covered by: ClaudeMetaGemini

奧羅茲最後問了每個工程師都在問的問題：在這個 AI 新時代，我要怎麼在一兩年內成為一位了不起的軟體工程師？納德拉的回答出乎意料地樸素：扎根於變化本身，真正理解它是什麼，而不是看新聞標題、陷入炒作週期。多做、多學、親手做，待在真正在做事的團隊裡。他自嘲在播客裡講這話有點諷刺：如果能改變自己「說」與「做」的比例，他會往「做」那邊加碼。無論是職涯中期、CEO 還是應屆畢業生，都一樣。

他給自己的總結是：什麼時候狀態最好？就是處於學習模式的時候。

Orosz closed with the question every engineer is asking: how do I become an amazing software engineer in this new age, in a year or two? Nadella’s answer was strikingly plain: get grounded in what the change really is, not headlines, not hype. Do more, learn more, get hands-on, be in teams that are doing. He joked about the irony of saying it on a podcast: “If I could change the ratio of my talk to do, I would do it.” Mid-career engineer, CEO or new grad alike.

His own summary: when is he at his best? When he’s in school mode.

所以，讓我們重新回到學校。“So let’s get back to school.”

主持人帶著振奮作結：產業確實在劇變，但在納德拉的描述裡，有海量的軟體工程工作等著被做出來：圍繞決策引擎這類新原語、以及尚未發明的原語去構建新系統；決定什麼放在哪裡、怎麼調整、怎麼部署，以及怎麼從中持續學習。

The host left it energised: the industry is in upheaval, but in Nadella’s telling there is an ocean of software engineering waiting to be done: building new systems around primitives like the decision engine and ones not yet invented, deciding what goes where, how to tune and deploy it, and learning from it.

帶回家的話Take-Home

納德拉的七句話

Seven lines from Nadella

  1. 程式碼便宜，驗證很難。把每次失敗變成測試案例。
  2. 不要愛上你做出來的東西。模型一躍進，產品形態就得改。
  3. 決策引擎是智能時代的預存程序。讓它像資料庫一樣無聊、可靠。
  4. 蓋工廠，不只做展示。規格、小任務、跨模型家族審查、生產軌跡回流。
  5. 擁有自己的學習閉環。harness、上下文、記憶、行動空間與模型分開；私有評估最重要。
  6. 權限與智能分開。把代理當內部威脅管理，思維鏈要人類可讀、可稽核。
  7. 回到學校。少說多做，永遠保持學習模式。
  1. Code is cheap; verification is hard. Turn every failure into a test case.
  2. Don’t fall in love with what you built. Model jumps change the product form.
  3. Decision engines are the stored procedures of the intelligence era. Make them boring and reliable.
  4. Build the factory, not just the demo. Specs, small tasks, cross-family review, production traces.
  5. Own your learning loop. Separate harness, context, memory, action space and models; private evals rule.
  6. Separate permissions from intelligence. Treat agents as insider threats; keep chains of thought readable and auditable.
  7. Go back to school. Talk less, do more, stay in learning mode.

這場小考教我的六件事

Six lessons from the test

  1. 同題不同卷。一句提示詞，得到 12、9、6 章三種答案，連繁簡都不同；要什麼就寫清楚。
  2. 流暢不等於忠實。排版最精緻、文筆最好的那份，正是唯一出現牴觸說法的一份。
  3. 引號是最該查的地方。模型最容易把自己的整理寫成「原話」。
  4. 用不同模型家族互審。三份交叉比對，多數決就抓出了誇大，正是納德拉說的方法。
  5. 先問資料從哪來。二手中文轉述與英文原稿，會寫出不同細節與日期。
  6. 匯出檔要清理。Gemini 的檔案夾帶平台注入腳本；上架前檢查原始碼。GPT 則連卷都沒交，工具能力本身就是門檻。
  1. Same prompt, different papers. One line yielded 12, 9 and 6 chapters, even different Chinese scripts; specify what you want.
  2. Fluent isn’t faithful. The most polished, best-written paper was the only one to contradict the others.
  3. Check the quotation marks first. Models readily present their own summaries as verbatim speech.
  4. Review with different model families. A simple majority vote across three caught the overstatement: Nadella’s own method.
  5. Ask where the material came from. A Chinese recap and an English transcript produce different details and dates.
  6. Clean the exports. Gemini’s file carried platform-injected scripts; inspect the source before posting. GPT didn’t deliver at all: tool access is itself a gate.
