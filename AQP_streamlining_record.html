01Installing the new file

  1. Keep a copy of the current AQP_gui_merged.m (for rollback).
  2. Put the new AQP_gui_merged.m next to the existing AQP_gui_merged.fig. The file name is unchanged on purpose: GUIDE finds the figure through gui_Name = mfilename.
  3. Launch as before: AQP_gui_merged, or with the console switches -d 1 -w 1 / -q / -v.

Nothing else is needed. The file is self-contained like the merged build; the only optional external dependencies are the LIBSVM binaries svmtrain_MEX / svmpredict_MEX, used only when run_SVR_yes is set.

Every callback in the .fig still exists

The .fig dispatches to 14 callbacks by name (Load_DS_Callback, Load_DS_CreateFcn, Run_AQP_Callback, close_figs_Callback, Cmp_Results_Callback, StepbyStep_plots_Callback, and the _Callback/_CreateFcn pairs of UDMas_scheme, CabXfer_scheme, cDataFlow, Lines_Xticks). All are present under the same names; the list was read out of the compressed .fig itself.

02What was merged or removed

2.1 Duplicate copies of the same helpers

The Aug 2026 merged file was built by folding standalone files (Run_AQP.m, Cmp_Results.m, StepbyStep_plots.m, Load_DS.m) back into AQP_gui.m. Each of those files had carried its own copy of the shared helpers, so the merged file held the same function 2–5 times under different prefixes.

Prefix in the merged buildFunctionsCame from
AQP_gui_merged__374AQP_gui.m helpers
Run_AQP__287Run_AQP.m (the live Run AQP path)
Cmp_Results__40Cmp_Results.m
StepbyStep_plots__7StepbyStep_plots.m
Load_DS__1Load_DS.m
AG_ / RA_4collision renames that hit the 63-character limit
no prefix211callbacks, ssds methods, Scan Thru, CmpR, verbosity, …

Finding them: every function body was tokenized (comments and whitespace ignored, references to other renamed copies normalized), and bodies were compared token by token, repeating until nothing changed. 334 names had more than one copy; 324 groups were token-identical outright and the other 10 differed only in comments or in which renamed copy they called (AG_… vs RA_…). One pair, tmp_folder_rm_mk__fdir_wildcard, differed by the onCleanup safety fix of 20 Aug 2026; the copy with the fix was kept. The extra copies amounted to 26,892 lines.

Naming rule: each group kept its plain name (the name of the original m-file) whenever that name was free — not defined elsewhere in the file, not a MATLAB/Octave built-in, and not used as a variable or field. Two helpers keep the prefix because the plain name is a built-in: AQP_gui_merged__cell2csv and AQP_gui_merged__append. The clipboard helper copy was renamed copy_to_clipboard so it cannot be confused with MATLAB's copy method.

Reachability was conservative: a function stays if any reachable function names it in code or inside any string literal, which covers feval, str2func and callback strings. A second pass on the finished file confirmed all 392 functions are reachable.

2.3 Merge scaffolding in comments

About 3,300 comment lines described the extraction/merge history rather than the program: %% ----- from Run_AQP.m section headers, [SSDS-LOCAL] and [EXTRACTED] banners, "This whole block is IDENTICAL in…" notes, orphaned headers of functions that no longer exist, and runs of separator lines. They were removed. Comments inside functions — your dated change notes and explanations — were left as they were; the function bodies are byte-identical to before apart from the changes listed in sections 03–05.

03Callback structure

Each button used to go through three functions, for example Run_AQP_Callback → Run_AQP(varargin) → Run_AQP__Run_AQP_Callback. Now a callback is one thin GUIDE entry point that calls a worker, commits the returned handles with guidata, and turns an error into a dialog.

ControlCallbackWorker call
Load_DS popupLoad_DS_Callbackhandles = Load_DS(handles)
Run AQPRun_AQP_Callback[handles, OUT_Cmp_Results] = Run_AQP(handles)
Compare ResultsCmp_Results_Callbackhandles = Cmp_Results(handles) → Cmp_Results_AQP(folder)
StepbyStep popupStepbyStep_plots_CallbackStepbyStep_plots(hObject, handles)
close figsclose_figs_Callbackcab(handles.hf_AQP)
Scan Thru (built in code)ScanThru_menu_Callback… Run_AQP(handles) per sweep point (was Run_AQP([],[],handles))

What the callbacks still do: Run_AQP_Callback pins the optional LIBSVM binaries to the path, remembers the working folder and restores it if the run fails, writes "AQP run FAILED" to the status line, refreshes the Compare Results button, and releases the in-memory store on failure. Cmp_Results_Callback keeps its two precondition checks (a run must exist; at least two Results files). StepbyStep_plots_Callback still resets the menu to row 1 on the error path.

Running without the GUI: the main function dispatches any local function by name, so the workers can be driven from the command line or a script:

% h = any struct with the same uicontrol fields as the GUIDE handles
h = AQP_gui_merged('Load_DS', h);              % asks for the dataset folder
[h, OUT] = AQP_gui_merged('Run_AQP', h);        % one full AQP run
AQP_gui_merged('Cmp_Results', h);               % compare the Results files

04In-memory data hand-off (AQP_mem)

The pipeline is a chain of stages — load workbooks, match wavelength grids, calibration transfer, pretreatment, PLS — and each stage handed its result to the next by saving an Atrainpketc_*.mat into a TMP folder; the next stage then listed the folder (get_OnlyOne_AT, fdir_wildcard…) and loaded the file back. A single run wrote 12–25 such files (4–19 MB) only to read them again.

AQP_mem is a store that lives for one run and plays the role handles plays in GUIDE or app plays in App Designer: a shared data context every stage can reach. All of those hand-offs now go through it.

  …

4.1 The rule: what lives where

LocationWhere the data goesNotes

A read that misses memory falls back to the disk, so a file that used to be found is still found. Folder listings merge memory and disk and return names in the same order Windows dir does (case-insensitive, NTFS collation). Keys are absolute, case-folded Windows paths, so ..\x, relative names and mixed / \ resolve to the same entry.

4.2 Life cycle

  1. Run_AQP creates TMP_AQP, then calls AQP_mem('begin', path_TMP_AQP): a fresh, empty store whose root is that folder.
  2. The stages read and write through the store during the run.
  3. At the end of Run_AQP (and in Run_AQP_Callback if the run fails) AQP_mem('reset') releases the memory. Peak use is about the size the TMP folder used to reach (4–19 MB in the tests).

4.5 Why a shared store instead of rewriting every function signature

The stages address their data by folder + file name: inp4AQP.path_CS_XRS, path_X_P, pathfnameTP4Val and so on are passed through about 40 functions and dozens of branches (woUDM/UDM schemes, DSn folders, Xfer-PP vs PP-Xfer, CS-only, woVal). Rewriting each hand-off as a function argument would have meant touching every one of those branches, including ones the test data cannot reach. Moving the medium to memory while keeping every naming and branching rule intact gives the same speed-up with behaviour unchanged by construction, and it can be proven byte-for-byte (07).

07Validation

Result

In all seven scenarios every deliverable file and the returned handles / OUT_Cmp_Results were bit-for-bit identical between the original and the new file. Where the original stops with an error (scenario C6), the new file stops with the same error at the same line.

7.1 Test environment

MATLAB is not available in the build environment, so both files were run in GNU Octave 8.4.0 (packages io 2.6.4, statistics 1.6.3, signal 1.4.5). Octave differs from Windows MATLAB in places, so a small set of test-only stand-ins was put on the path. The same stand-ins were used for both versions, so the comparison is like-for-like; neither program file was edited for testing apart from one identical, automatic transform (below).

09How-to recipes

Inspect an intermediate data set

Set MIRROR_TMP_TO_DISK = 1; in INTERNAL_SETTINGS, save, run. The stage files appear in TMP_AQP exactly where the old builds wrote them.

See how much the store holds during a run

s = AQP_gui_merged('AQP_mem','stats')   % .nfiles  .MB  .root
% (the store is emptied when Run_AQP finishes)

Run the pipeline from a script

h = guidata(findall(0,'Name','AQP_gui_merged'));   % handles of the open GUI
[h, OUT] = AQP_gui_merged('Run_AQP', h);
disp(OUT.Path4OUT_cln_AQP_FinalSubfolder)

A stage reports a missing Atrainpketc file

  1. Rerun with AQP_gui_merged -d 1 -w 1 to see the console messages.
  2. Set MIRROR_TMP_TO_DISK = 1: if the run then succeeds, a raw dir/load outside the converted sites is reading a TMP file — note the function from the error and replace that call with aqp_load / aqp_merge_names.
  3. For an urgent run, the previous AQP_gui_merged.m still works with the same .fig.

Find where an old function went

Use the lookup in section 10: type any part of the old name.
