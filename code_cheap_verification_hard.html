中文摘要Chinese summary

AI 把軟體工程的瓶頸，從「寫」移到了「證明對」。

  1. 一規格先行：程式碼成為輸出，意圖與設計文件才是核心；規格模糊，只會更快產出錯誤程式。
  2. 二軟體工廠內建驗證：任務切小，失敗轉成測試，用不同模型家族互審，生產日誌回流形成可驗證閉環。
  3. 三可靠勝過聰明：決策引擎要像資料庫一樣無聊、可預測。
  4. 四棕地最難：改既有系統，卡在建置與 CI/CD。
  5. 五信任架構：權限與智能分開，思維鏈可稽核，私有評估優先。

本頁本身即是例證：三份答卷交叉比對，抓出 Gemini 的誇大。流暢不等於忠實，信任才是新的成本。

English Summary英文摘要

AI has moved software engineering’s bottleneck from writing code to proving it’s right.

  1. 1Spec first. Code is now an output, so intent and design docs are the core work. A fuzzy spec just produces wrong code faster.
  2. 2Build verification into the factory. Keep tasks small, turn failures into tests, and review with a different model family. Feed production logs back in to close a verifiable loop.
  3. 3Reliable beats brilliant. Decision engines should be as boring and predictable as a database.
  4. 4Brownfield is hardest. Changing existing systems gets stuck at build and CI/CD.
  5. 5Trust architecture. Keep permissions separate from intelligence, keep reasoning auditable, and put private evals first.

The source page itself proves the point. Cross-checking the three papers caught Gemini’s overstatement. Fluent isn’t faithful, and trust is the new cost.

附註：什麼是 CI/CD？Note: What Is CI/CD?

CI/CD ＝ 持續整合／持續交付（或持續部署）· Continuous Integration / Continuous Delivery (or Deployment)：把程式碼變更一路自動送上線的流水線。

  1. CI持續整合：每次提交程式碼，系統自動建置並執行測試，幾分鐘內就抓出錯誤，不讓問題累積。
  2. CD持續交付／部署：通過的程式碼自動打包、送到測試或正式環境。「交付」在上線前停下等人核准；「部署」則全自動上線。

與納德拉論點的關係：CI/CD 就是驗證真正發生的地方。AI 寫程式便宜了，這條建置、測試、檢查的流水線，就是決定什麼能安全上線的關卡。在 Windows 這類棕地系統，流水線老舊、龐大、緩慢，於是成了瓶頸。

化學計量學的類比：像一條自動品管線，每個新校正模型都要先用標準樣品驗證，才准裝上儀器。

CI/CD stands for Continuous Integration / Continuous Delivery (or Deployment): the automated pipeline that takes a code change all the way to production.

  1. CIContinuous Integration: each commit is automatically built and tested, so errors are caught within minutes instead of piling up.
  2. CDContinuous Delivery/Deployment: code that passes is automatically packaged and released to staging or production. Delivery stops for a human to approve; Deployment ships with no manual step.

Why it matters for Nadella’s point: CI/CD is where verification actually happens. When AI writes code cheaply, the pipeline of builds, tests and checks is the gate that decides what’s safe to ship. In brownfield systems like Windows, that pipeline is old, huge and slow, so it becomes the bottleneck.

Chemometrics analogy: an automated QC line, where every new calibration model is validated against reference samples before it’s allowed onto the instrument.
