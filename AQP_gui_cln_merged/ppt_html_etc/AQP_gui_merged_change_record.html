1. What was merged

The session opened with a related question — whether the ssds.m classdef was still needed with AQP_gui.m as the main program. It was not: all 147 ssds references already resolved to the in-file [SSDS-LOCAL] block. That answer set up the merge, since it confirmed nothing in the closure required a separate class file.

Everything then went into one file. Nothing had to stay separate — there was no classdef and no script in the set, so the usual "these files can't be inlined" caveat did not apply.

2. Collision policy

337 names were defined in more than one source file. None were dropped on the assumption that two copies were identical. The file that owns a name as its primary keeps it; every other host's private copy became <hostfile>__<name>, with that host's internal references rewritten to match. Each half therefore keeps calling exactly the copy it always called.

The ssds split shows the shape of it cleanly:

147 calls in the AQP_gui body  ->  AQP_gui_merged__ssds
 53 calls in the Run_AQP body  ->  Run_AQP__ssds
  0 bare ssds( left anywhere

Duplication across the two halves is correct and behaviour-identical, because each host uses its own private copy — exactly as separate files resolved before the merge.

4. Defect ledger

Five defects surfaced after the first build. They are numbered in discovery order, because that order matters: each one was masking the next.

D1The fig would not read at all
Symptom
Dot indexing is not supported for variables of this type in FigFile/read, at hgDataVars.(vars_hgM{1}).GraphicsObjects.Format3Data.
Root cause
A MAT-file header stores the byte offset of the subsystem element at bytes 116–123. That element holds __function_workspace__, and hgM_070000.GraphicsObjects is an MCOS object living inside it. The header was copied verbatim while the body was re-serialized, so the offset still said 11665 when the element had moved to 8353. MATLAB read the subsystem from the wrong place and got garbage.
Fix
The patcher now records which element the old offset pointed at and rewrites bytes 116–123 with its new position.
D2Four names past the 63-character limit
Symptom
'Run_AQP__find_keyword_merge_dual_curly_bracket_w_targetstring_remain' exceeds the MATLAB maximum name length of 63 characters and will be truncated.
Root cause
The <hostfile>__ collision prefix pushed four already-long helper names over the limit. MATLAB does not error on this — it truncates and warns, which silently detaches a definition from its call sites.
Fix
Short host tags AG_ and RA_ on those four only; 39 references rewritten. Longest name is now exactly 63, and no two names collide when truncated at 63.
D3Four dead fig entry points
Symptom
None yet — caught by audit before it could fire. Every one of the four main buttons would have thrown Undefined function on click.
Root cause
Load_DS.m, Run_AQP.m, Cmp_Results.m and StepbyStep_plots.m each carry their own copy of the callback body they were extracted from, while AQP_gui.m keeps the delegating stub. Neither copy is its file's primary, so the collision rule renamed both — leaving no plain Load_DS_Callback etc. for the fig to dispatch to.
Fix
The GUI stub reclaims the bare name, since it is the entry point the fig calls by string. Each extraction's private copy keeps its prefixed form. Required names are now read out of the fig rather than listed by hand, so the check covers all 16 dispatched callbacks.
D4A second copy of the callback text
Symptom
Fig opened, but six CreateFcn errors at load: AQP_gui is not found in the current folder or on the MATLAB path.
Root cause
GUIDE stores each callback's text twice. Once in hgS_070000 as a readable MatlabFunction property — which is what had been patched, and what read back correctly. And once inside the __function_workspace__ MCOS blob as miUTF8 char data. MATLAB rebuilds the handle from the second copy. Only the six CreateFcns fire at load, so only they complained; the ten Callbacks were equally broken and would have failed on first click.
Fix
The blob turns out to be a complete MAT element stream in its own right — an 8-byte version prefix followed by ordinary miMATRIX elements — so the same parser reached in and patched all 16. It grew 114,840 → 114,952 bytes, which meant fixing the enclosing uint8 array's dimensions too.
D5The spoken SamLibrary.dll nag
Symptom
An audible complaint about SamLibrary.dll on every .sam export pass.
Root cause
Speak_mk was only the megaphone. load_SamLibrary looked in exactly one place — which('SamLibrary.dll') — and with the dll off the path that returns '', so NET.addAssembly('') threw and the caller spoke the error unconditionally. Worth noting: the hard-coded samLibPath computed a few lines above was dead code, left stranded when someone commented out the try/catch that used it.
Fix
Four candidate locations tried in order (path, the revived hard-coded mainPath, beside AQP_gui_merged.m, then pwd), with NET.addAssembly called only on a path that exists. The outcome is cached in a persistent, and a second output tells callers whether this is a first failure — so it loads silently when found, speaks once per session when not, and stays quiet thereafter.
To get .sam output working Drop SamLibrary.dll beside AQP_gui_merged.m or addpath its folder; on success the console shows load_SamLibrary: loaded <path>. To skip .sam entirely, the GUI already has the switch — handles.Option_Output set to Output_SAM_yes=0 bypasses the block, dll and all.

5. How the .fig was patched

A GUIDE fig is a MAT v5 file, and the callbacks are serialized anonymous function handles whose source text hard-codes the main file's name:

@(hObject,eventdata)AQP_gui('Load_DS_Callback',hObject,eventdata,guidata(hObject))

MATLAB rebuilds the handle from that text on load, so renaming the fig alone fixes nothing. The replacement is seven characters longer than the original, which rules out a byte patch: every char array's dimensions, every enclosing miMATRIX byte count, the outer zlib element and the header offset all have to be recomputed.

So the file is parsed into an element tree, edited, and re-serialized. Three format details mattered:

  • miCOMPRESSED elements are not padded to 8 bytes, unlike every other type. Getting this wrong on the first pass sent the parser off the rails after the first element.
  • The header's subsystem offset must be recomputed — D1.
  • The workspace blob is a nested MAT stream holding a second copy of every string — D4.

A lossless round-trip was verified before any edit: hgS_070000, hgM_070000 and __function_workspace__ all came back byte-identical through an independent MAT reader.

Deliberately left alone

The figure's Name property is still AQP_gui, so the window title reads that way. This is on purpose: AQP_gui_OutputFcn finds the window with get_handles_from_GUI_Name('AQP_gui'), which matches on Name rather than filename, and any external tool that looks the window up by name keeps working. Changing it is a two-line edit on both sides.

The IsOKToExecuteAqpLite returned FALSE message seen during testing comes from the pre-existing user gate reading getenv('username') — independent of the merge.

8. Finding the edits later

Every change to the moved or merged code carries a searchable tag. Grep [MERGED 25 Aug 2026] to find all of them: the header banner, the five pre-flight guards, the two load_SamLibrary rewrites and the four call sites. Earlier provenance tags from previous sessions — [SSDS-LOCAL], [EXTRACTED], [DELEGATED, Aug 2026] — are preserved untouched.

The header block of AQP_gui_merged.m also records the two facts most likely to confuse a future reader: which four callback names must keep their bare form because the fig dispatches to them by string, and which four helpers use the short AG_ / RA_ tags because of the 63-character limit.
